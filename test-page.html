Fullsize — resolver test fixture

Dev-only. Not part of the shipped extension.

Before this page can work: Chrome does not run content scripts on file:// URLs by default. Go to chrome://extensions → Details on the Fullsize card → turn on Allow access to file URLs. Then reload this page.

1. Wikimedia thumbnail strip

Displayed at 250px- (~41 KB). Stripping /thumb/ and the NNNpx- prefix reaches the original. Expect: 800×600 PNG, ~225 KB.

2. Query-param resizer (imgix / Unsplash style)

Displayed with ?w=300&q=60 (~11 KB). Dropping the resize params requests the source. Expect: ~4.7 MB JPEG — the biggest win on this page.

3. srcset with w descriptors

Three advertised widths; the browser will have loaded a small one. Expect: the 1600w entry beats currentSrc, then param-stripping beats that.

4. <picture> with <source>

The high-res entries live on the sibling <source>, not the <img> — the case most tools miss. Expect: the 2000w source is found even though the img tag only knows the small URL.

5. Lazy-load attributes

Real URL parked in data-src; a script swaps it in after a delay, so the image does not exist in the DOM at document_idle. Expect: the hover button still appears (proves event delegation covers late images).

6. WebP source (format conversion — Milestone 4)

Served as image/webp. Expect: "Original" saves a .webp; PNG and JPG produce genuinely converted files.

7. Shopify _400x400 pattern

A live Shopify CDN URL. This asset is small at every size, so the byte count will not change — it is a pattern test. Expect: candidate list contains the stripped shopify-logo.png, and it loads (no 404 fall-through).

8. 16×16 spacer (must be ignored)

Expect: no hover button at all — below the 64×64 minimum.

9. Resolver dry-run (no network)

URL patterns that are awkward to host live. From Milestone 3, run __fullsizeDryRun() in this page's console to print the candidate list each one produces, and check it against the expectation.
